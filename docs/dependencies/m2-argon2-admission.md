## Need and proposed graph

Human-selected dashboard passwords require the approved memory-hard Argon2id verifier. Python's standard library does not provide Argon2id; implementing cryptography in-house is rejected. The candidate is the documented high-level `PasswordHasher`, explicitly configured for `Type.ID` and an approved versioned parameter policy, not a low-level custom binding or a test-only hasher. Its API supports random salts and rehash detection; upstream warns that its defaults may change, so defaults must not become an implicit product policy. [Upstream API](https://argon2-cffi.readthedocs.io/en/25.1.0/api.html), [upstream security policy](https://github.com/hynek/argon2-cffi/security/policy).

The following is the **approved Linux candidate graph**, not yet a resolved or installed lock. PyPI's exact-release metadata reports `argon2-cffi` → `argon2-cffi-bindings` → `cffi>=1.0.1` on Python 3.12 → `pycparser` on CPython. Exact transitive pins below require lock and clean no-build verification; a resolver deviation returns to review.

FastAPI, SQLAlchemy, Alembic, pytest, and Playwright retain their separate M1 admissions if their exact locked versions do not change.

## Security, maintenance, and provenance review

The two Argon2 packages are maintained by Hynek Schlawack with recent tagged releases and explicit latest-only [high-level](https://github.com/hynek/argon2-cffi/security/policy) and [bindings](https://github.com/hynek/argon2-cffi-bindings/security/policy) security policies. `cffi` and `pycparser` have the exact release dates above; `cffi` has no published GitHub `SECURITY.md`, while `pycparser` has a latest-only policy. None of these facts promises a time-bounded support horizon. The four PyPI exact-release records and OSV `/v1/querybatch` queries for the four `PyPI` name/version tuples returned zero listed advisories on 2026-09-20 (HTTP 200). This is a point-in-time registry/advisory lookup, **not** proof of absence or an approval of the graph. Recheck immediately before lock change and on updates. [OSV API](https://osv.dev/docs/).

PyPI publishes SHA-256 digests and provenance metadata for candidate artifacts. The selected pure wheels have SHA-256 `fdc8b074db390fccb6eb4a3604ae7231f219aa669a2652e0f20e16ba513d5741` (`argon2-cffi`) and `b727414169a36b7d524c1c3e31839a521725078d7b2ff038656844266160a992` (`pycparser`). For CPython 3.12, the Linux x86-64 wheels are bindings ABI3 `27f1821903e2ceadcb88ec2b45ef190897b7682449c772f4d9b53e42c520cf29` (manylinux glibc 2.26+) and CFFI `c1453022f490d2459a11819d83ad1d586e9ff65a12ac3e705ffebd46d3685dcf`; macOS ARM metadata lists bindings ABI3 `21ca0396fe5ec995dd54431c32698189666f9224810acfa752e50d2bd94d9df2` and CFFI `f81b3b8f3d4e343550fa4baa0e479bba9f2d29ce9c2e9b51d1ce1718d7442fcf`. The four Linux wheel archives were downloaded to a temporary review directory with `pip download --only-binary=:all: --no-deps` and independently hashed using `sha256sum`; all four matched these published digests. Their wheel metadata confirms the exact four-package graph and license expressions. The current bindings release publishes no macOS x86-64 wheel; a no-build install on Intel macOS is therefore **Blocked** pending a platform/version/build decision and real macOS verification. [Bindings installation guidance](https://argon2-cffi.readthedocs.io/en/25.1.0/installation.html).

The binding and CFFI wheels contain native code. Inspection of all four Linux wheel archives found one native shared library in each of the binding and CFFI wheels, their declared `dist-info` license files, no install script, and no extra executable. The CFFI tagged source has a separate `src/c/libffi_x86_x64/LICENSE` with an MIT notice, which must be retained if that code is redistributed. CFFI's `MIT-0` is an [OSI-approved permissive license](https://opensource.org/license/mit-0); the root reviewer explicitly classifies it as acceptable for AgentMonitor's proprietary local/Linux use under the policy's ordinary-admission discretion, not as exact MIT. This is an engineering classification, not legal advice. Use only hash-verified wheels from the approved registry with source builds disabled; no unreviewed sdist build, install hook, or telemetry is authorized. Public metadata/upstream documentation names no AgentMonitor-facing network/analytics behavior; this static observation is **not** a runtime outbound-traffic test. Published wheel sizes are small (roughly 15 KB high-level, 27 KB Linux binding, 222 KB Linux CFFI, 48 KB parser), but hashing CPU/memory and concurrent-login impact are **Not Run**.

## Approval conditions and lifecycle

1. **Passed for Linux admission:** root dependency/security review on 2026-09-20 classifies MIT, MIT-0, BSD-3-Clause, and the identified CFFI/libffi MIT notice as compatible with local/proprietary use. Four exact Linux wheels, metadata, license files, native inventory and SHA-256 values were inspected. The latest advisory lookup returned no listed finding, not a guarantee. Distribution still needs complete generated notices/SBOM and a release-specific license review; macOS Intel remains outside this approval.
2. **Approved M2 Linux policy:** Argon2id RFC 9106 low-memory profile, explicit `memory_cost=65536` KiB, `time_cost=3`, `parallelism=4`, `salt_len=16` bytes, `hash_len=32` bytes, and PHC version 19; no configuration or test mode may lower it. Bound password input at 1,024 UTF-8 bytes and at most two simultaneous password hash/verify operations per service process. The target-workstation acceptance budget is p95 verification under 250 ms and process peak RSS under 256 MiB at two workers; failure calls for capacity review, never weaker parameters. On 2026-09-20 the real upstream `python -m argon2 --profile RFC_9106_LOW_MEMORY` ran 100 verifications at 55.0 ms mean and `/usr/bin/time -v` reported 80,276 KiB peak RSS. A second real 100-verification two-worker run measured p50 89.41 ms, p95 100.19 ms, 4.48 s total, and 150,500 KiB peak RSS. These are admission benchmarks on the target Linux machine, not automated application tests or macOS evidence; the same profile must be used in production and codified for repeatable review.
3. After this dependency admission, add the exact direct pin to the manifest, resolve a fresh lock, verify the resulting four-package graph and applicable wheel hashes, run frozen `--no-build` installation, real hash/verify/random-salt/rehash tests, license/security scans, and regenerate SBOM/notices. Any unexpected version, native artifact, license, build hook, or advisory returns to review before use.
4. Reassess on every dependency update; keep prior PHC verification compatibility or use an approved credential-recovery transition. Removal requires an approved maintained Argon2id replacement and migration/rehash plan. No password or PHC string enters this record, artifacts, logs, or examples.

**Current gate:** Exact Linux package graph and password-hashing profile admitted; real upstream Linux benchmark passed the stated admission budget. Production adapter tests, project lock/SBOM/notices, live operator bootstrap, migration, API, and browser tests are **Not Run**.
