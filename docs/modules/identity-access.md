# M01 identity/access — V1-M2 Stories 1–2

- Owner: `PLAN-M01`; implementation slices `ST-IAM-001/002`.
- Published contracts: `CTR-IAM-001..005/007/008` V1; shared database contract `CTR-DB-002` V1.
- Status: Stories 1–2 have real SQLite tests; Story 2 independent review and the M2 HTTP/browser gate remain pending. Live owner bootstrap and installed recovery are separate gates.

## Boundaries and state

`modules/identity_access/domain/policy.py` contains deterministic policy only. `application/bootstrap.py` consumes repository and hasher protocols. `adapters/identity_access/argon2_password.py` is the only Argon2 implementation; `adapters/persistence/identity_access/sqlite/repository.py` owns `iam_*` writes. `adapters/identity_access/tty_operator.py` handles local no-echo input; `composition/iam_operator.py` wires the production bootstrap command. P01 must use published M01 application ports, not the repository or tables directly.

The immutable Alembic chain has `v1_0000 → v1_0100`. The latter creates exactly seven IAM tables, no credential row, and one nullable safe `reason_code` audit column. The catalog pins revision bytes; the runtime separately checks exact admitted IAM table/index DDL, including columns, foreign keys, checks, and index definitions. Fresh initialization accepts only a previously absent database file. Existing empty or `v1_0000` files are preserved and refused until a separately approved offline backup/quiescence upgrade workflow exists. No startup DDL or downgrade is available.

## Local operator sequence

Run from the repository root as the normal owner user, never root. Use an absolute owner-only (`0700`) data root; never pass a password in argv, `.env`, stdin redirection, or shell history. This is the current M2 development/local flow; `backend/pyproject.toml` has `package=false`, so a plain system `python -m` invocation is not installed or supported.

```bash
PYTHONPATH=backend/src backend/.venv/bin/python -m agentmonitor.composition.iam_fresh_init --data-root ABSOLUTE_0700_ROOT
PYTHONPATH=backend/src backend/.venv/bin/python -m agentmonitor.composition.iam_operator bootstrap --data-root ABSOLUTE_0700_ROOT
```

The first command is the M2-only fresh absent-file initializer, not an existing-file migration/backup routine. The second command requires a controlling TTY and asks for password plus confirmation with echo disabled. It creates one implicit administrator and one safe audit event atomically. A second bootstrap refuses without prompting for another password. The commands are installed/composed by the integration steward; live owner password entry is still Not Run. Do not use a test database as a replacement for the owner's real setup.

If the stored policy version is incompatible, the operator command returns `iam_repository_unavailable` without a password prompt or database mutation. It must not misreport that state as an ordinary already-initialized installation.

Recovery is intentionally not an installed command yet. The repository transaction can rotate the verifier and revoke every stored session/token in one transaction, but an operator entrypoint needs a service-held quiescence receipt and later credential-populated integration verification. No HTTP setup or recovery endpoint is permitted.

## Password and audit policy

New passwords require at least 15 Unicode code points and at most 1,024 UTF-8 bytes; malformed Unicode fails safely. The admitted Argon2id profile is 65,536 KiB, three passes, four lanes, 16-byte random salt, 32-byte tag, PHC version 19, with at most two simultaneous operations. Only PHC verification material is stored, never plaintext. Story 2 adds exact allowlisted event/outcome/target/actor/count pairs for login success, throttle activation, session expiry/revocation, bulk revocation, and password change. The database audit row permits only bounded technical fields, not token names, raw request text, credentials, or provider content. CSRF and authorization-denial event aggregation is not yet implemented and cannot be claimed as passed.

## Browser authentication and session ports (Story 2)

`application/sessions.py` publishes `AuthenticateAdministratorV1`, `ResolveBrowserSessionV1`, `VerifyCsrfV1`, `LogoutSessionV1`, `ListSessionsV1`, `RevokeSessionV1`, `RevokeAllSessionsV1`, and `ChangeAdministratorPasswordV1`. `application/authorization.py` publishes `AuthorizePrincipalV1`; only the closed M2 browser permission set and current bearer permission set can be granted. This is dashboard authorization, not provider reauthentication. The SQLite adapter owns only M01 tables; P01 must supply validated Host/Origin/cookie transport and a bounded request correlation ID to every M01 operation, then call these ports, never the repository directly. A request-triggered expiry audit uses that exact caller ID, not a generated replacement.

Each successful password login creates a fresh CSPRNG session credential and a separate CSRF credential. Both issue together in a redacted, nonserializable `SessionCredentialIssueV1`; no existing secret can be queried or replayed. SQLite stores a public selector and SHA-256 digest of the full session credential plus a separate CSRF digest, never the plaintext. `ResolveBrowserSessionV1` compares verification material safely, evaluates the persisted idle and absolute deadlines at the real UTC time, and returns a safe principal/summary. The fixed idle deadline is 1,800 seconds and the absolute deadline is 43,200 seconds; equality is expired. Accepted requests at least 60 seconds after the last persisted activity atomically move the idle deadline to `min(now+1800, absolute)` and increment the version. Requests inside that interval do **not** claim a freshly durable 30-minute deadline; early expiry by less than 60 seconds is possible after restart. A revoked credential never becomes active again. On the first observed expiry in an authentication, CSRF, mutation, or bounded session-list path, M01 atomically records terminal reason `expired`, nulls both digests, advances the version, and appends a safe expiry audit event. Subsequent backward wall-clock movement cannot resurrect that observed-expired credential. A real elapsed deadline and clock rollback have not yet been tested.

`VerifyCsrfV1` requires a bounded CSRF cookie/header pair matching each other and the digest stored for that still-active session. Every M01 browser mutation rechecks actor activity and CSRF inside its own `BEGIN IMMEDIATE` transaction; a separate earlier proof check alone does not authorize a later mutation. A stale resolved principal is rejected by `ListSessionsV1` after its backing session is revoked. Session listing is browser-only, ordered by issue time/ID, with a limit of 1–200 and a validated opaque session-ID cursor. Target and bulk revocation null credential/CSRF digests and append safe audit facts atomically. A bulk administrator action labels all previously nonterminal targets `administrator` even if an unobserved deadline had already passed; the label describes the actual invalidating operation, not a prior observed expiry. Its affected count is rows administratively terminalized, not necessarily sessions active immediately before the request. Bulk revocation retains the current session; its digest-only 24-hour idempotency receipt references the safe audit event for exact replay count and detects a different actor-session exclusion as `idempotency_key_reused`.

The installation-global durable throttle permits four invalid attempts and locks on the fifth for 30 seconds. A lock expiring inside its 900-second window preserves the threshold count, so the next failure escalates to 60 seconds; subsequent locks double up to 900 seconds. A window expiry clears the failure count but not consecutive-lock history; verified success clears both. Locked attempts skip Argon2. Password change also verifies the current password under this throttle, checks current actor session version and CSRF in the same transaction, replaces the PHC, revokes all old browser sessions, and issues one fresh binding. API tokens are independent and remain untouched. A password-change replay from an old revoked cookie fails authentication first; a fresh valid session presenting the same key receives `one_time_secret_not_replayable`, never a second secret or PHC mutation. Neither the receipt nor audit stores a password-derived fingerprint.

The Story 2 real-boundary matrix and Red/Green evidence are in [the Story 2 record](../evidence/m2-st-iam-002.md). HTTP cookie flags, Origin/Host denial, generated OpenAPI/client, built-browser behavior, actual 30-minute expiry, 24-hour receipt expiry, and provider/account authentication remain separate Not Run gates. No provider profile, running agent, `.env`, or external account is accessed by these M01 tests.
