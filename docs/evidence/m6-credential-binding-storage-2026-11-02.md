# M6 credential binding storage slice

This M02 slice implements `CTR-REG-011` 1.0.0 storage and additive SQLite revision `v1_0709` after `v1_0708`. The new tables contain non-secret binding handles, generation, owner-asserted association and lifecycle state; partial unique indexes enforce one active and one pending item per account, and the binding primary key is globally unique. `BEGIN IMMEDIATE` serializes transitions and version/generation comparisons. New handles are generated internally. No provider account or secret was created for testing.

The real empty-file migration schema test failed first because both new tables were absent, then passed with the schema installed. Domain lifecycle tests passed. Real account transition, concurrent rotation, OS Secret Service interaction, atomic cross-module observation-commit fencing, provider and dashboard validation are **not run**. The repository is not yet wired to production collection or a keyring workflow and the slice is not an M6 completion claim. In particular, cross-module generation validation must be part of the same observation-commit transaction; a prior read is not sufficient.

Existing databases require the approved offline backup and upgrade workflow; this migration does not support downgrade. Recovery is forward repair or restoring a verified pre-upgrade backup, which loses post-backup changes. Deployment and backup/restore verification remain outstanding. No live database or service was changed.

Archive correction: an Ollama account archive invokes binding invalidation inside the same `BEGIN IMMEDIATE` account transaction, before the account update. Nonterminal bindings become `cleanup_pending` and the binding generation advances; an update mismatch aborts the whole archive. A binding read for an archived account fails closed if nonterminal bindings are found. The new pure visibility test failed before its implementation and passed afterward. Real account archive, concurrent archive/rotation, cleanup in Secret Service and cross-module commit fencing remain **Not Run**; no synthetic account was inserted into SQLite.

Integration candidate verification: the real empty SQLite schema and pure
binding lifecycle suite passed, 13 tests. This does not establish the
unexecuted real-account and concurrent-transition scenarios above.

`AUTO-MIGRATE` now supports the explicit offline paths `v1_0603`, `v1_0707`, and `v1_0708` to `v1_0709`. Against separate real empty prior-revision SQLite databases, the canonical command produced and verified a private pre-upgrade backup and reached the new head for each source; the previous `v1_0603` test also verified an already-current retry. The `v1_0708` case failed before the change because the source revision was not accepted, then passed. These tests do not exercise existing business records, a deployed service, recovery by actually restoring a backup, or Secret Service items. The procedure retains its original offline/quiescence, backup, and forward-fix/restore limitations; it does not restart services or automatically restore a failed upgrade.
