# M6 quiescent-stop investigation

A reusable isolated process-inspection primitive and real disposable systemd tests have been prepared for the approved dashboard rollout work. This is **not a cutover command**, deployment, backup, restore, or M6 completion result. It has no CLI and must not be called against the installed dashboard without a separate orchestrator establishing the service identity and shared transition lock.

The primitive requires an already-running unit with effective `Restart=no`, pins its main PID with a Linux pidfd, stops it, verifies every thread is stopped and has no children, recursively checks the unit cgroup contains only the main process, rechecks unit properties and the frozen process, then signals only that pinned main process. Failure before the kill resumes it. It does not stop or signal any child process. Tests used disposable real systemd services and real processes: a child-free service stopped; a child under the main thread was refused and the parent resumed; a worker-thread child was found even when the leader's children file was empty. The tests do not prove a full rollout or protect against noncooperating operators changing the unit outside the transition lock.

Earlier disposable tests showed that direct SIGKILL with `Restart=on-failure` restarts the service, a temporary `Restart=no` drop-in with daemon reload affects the running service, and a systemd stop job sends SIGCONT and can permit a waiting worker to spawn a child. An isolated SQLite WAL test recovered an uncommitted schema transaction after a killed writer, but it did not test the owner database. The installed dashboard was not stopped.

Still required before an executable safe cutover: select and independently verify the exact live unit/process/revision, install and reliably restore a temporary restart override, prevent concurrent deployment operations, stop safely, private backup and migration, validate the candidate, and implement/test stopped-service backup restoration. In particular, do not blindly restore an old backup after a new service has accepted writes; that would lose those writes. Verify non-SQLite owner settings and recovery of interrupted writes. Real authenticated dashboard, LAN and provider continuity checks and full migration rollback remain Not Run.

Hardening follow-up: the stop primitive requires the independently selected PID, cgroup, start ticks, executable device/inode, systemd InvocationID and monotonic start identity. After opening the pidfd it revalidates those facts, UID, cgroup and systemd identity before the first signal, then checks them again while frozen. It refuses unless `RefuseManualStart=yes` and `Restart=no` are effective. A disposable real-unit test was Red before the start-block precondition and Green after it. A separate real two-service test uses the other process's actual PID, cgroup, start identity, executable and systemd invocation, one at a time, and verifies that every mismatch is refused while the selected service remains running. These are isolated tests, not a cutover, identity approval or live dashboard verification.
